自分で作るなら？・どう応用できる？

【自分で作るなら：開発チーム向け】

1. データを取得

- GitHub ActionsでPRの差分、Issue本文、ファイル一覧を取得

2. AIへ渡す

- OpenAI APIやChatGPT/OpenAI Agentsに、変更点、関連ルール、過去のレビュー観点を送る

3. AIで処理

- PR差分の要約

- 危険な変更点の抽出

- レビュー観点ごとの指摘生成

- Issueの分類（バグ、要望、質問など）

4. 保存

- GitHub review comments に投稿

- 必要ならGoogle SheetsやNotionにログ保存

5. 通知

- Slackやメールで「要確認PR」「高優先Issue」を通知

6. 人間が確認

- 開発者・レビュアーが採否を決める

【仕事への応用例】

1. カスタマーサポートの一次振り分け

- 入力: 問い合わせ本文

- AI処理: 緊急度、カテゴリ、担当部署候補を判定

- 出力: Slack/チケットシステムへ転送

- 人間: 重要案件だけ確認

2. 社内申請の事前チェック

- 入力: 申請内容、添付ファイル

- AI処理: 不足項目や規程違反候補を抽出

- 出力: 申請フォームの指摘欄へ反映

- 人間: 承認可否を判断

3. 議事録からタスク化

- 入力: 会議メモや文字起こし

- AI処理: 決定事項、担当者、期限を抽出

- 出力: Notion/Trello/Jiraに登録

- 人間: タスクの優先度を調整

4. 品質確認の初回レビュー

- 入力: 原稿、提案書、仕様書

- AI処理: 抜け、表記ゆれ、矛盾を指摘

- 出力: コメント付きで返却

- 人間: 最終校正

【個人利用の応用例】

1. 家計メモの分類

- 入力: レシート写真やメモ

- AI処理: 食費、交通費、日用品に分類

- 出力: Google Sheetsへ記録

- 人間: 月末に確認

2. 旅行準備の抜け漏れチェック

- 入力: 行程表、持ち物リスト

- AI処理: 天候や日程に応じた不足項目を指摘

- 出力: チェックリスト化

- 人間: 最終確認
