なぜこのAI活用が有効だったのか

有効だった理由として考えられるのは、フォーム入力のように手順が比較的定型で、入力項目が明確な作業だったことです。さらに、PlaywrightベースでDOMやアクセシビリティツリーを使えるため、画像認識や座標依存よりも安定して要素を操作しやすい点が効いています。これは記事の事実に基づく部分と、定型業務に向くという分析の両方を含みます。

この事例から学べること

再利用しやすいポイントは、1) 入力項目が決まっている業務を選ぶこと、2) 自然文のメモをそのまま渡すのではなく、必要項目を整理してLLMに渡すこと、3) ブラウザ操作はLLM単独ではなくPlaywrightのような実行ツールと組み合わせること、4) APIがないサービスでも自動化候補にできることです。特に、最初から複雑な業務を狙うより、まずはフォーム入力や申請送信のようなシンプルな流れから始めるのが現実的です。

自分で作るなら？・どう応用できる？

仕事への応用例

1. 経費申請の下書き作成：Slackやメール本文から、日付・金額・用途・取引先名を抽出 → LLMで申請フォーム用の項目に整形 → ブラウザで申請画面へ入力 → 人間が最終確認して送信。

2. 問い合わせ管理の転記：問い合わせメールを取得 → LLMで件名、要約、緊急度、担当部署を分類 → CRMや管理画面へ入力 → 担当者へ通知。

3. 出欠・予約申請の代行：会議案内や依頼文から候補日時・人数・場所を抽出 → 予約サイトや社内フォームに入力 → 送信前に人が確認。

4. 定型報告の登録：日報メモを取得 → LLMで「実施内容」「課題」「翌日対応」に整形 → Notion、Google Sheets、社内システムに登録 → 上長に通知。

個人利用の応用例

1. 旅行の予約メモ整理：メールやメモから宿泊日程・人数・希望条件を抽出 → 予約サイト入力用に整形 → 自分で最終予約。

2. 各種申請の補助：保険や自治体の申請で、手元のメモや必要情報を整理 → フォーム入力前の下書きを作成 → 本人が確認して提出。

3. 反復入力の補助：イベント申込や会員登録で、氏名・住所・連絡先を整形 → ブラウザ自動入力 → 提出前に目視確認。

実装するなら、例えば次の流れです。

1. Slack、メール、Googleフォーム回答、CSVなどから入力データを取得する

2. ChatGPTやOpenAI APIで必要項目を抽出・整形する

3. PythonでPlaywrightを呼び出し、Webフォームへ自動入力する

4. 入力結果をExcel、Google Sheets、Notion、DBに保存する

5. 完了時にSlack、メール、Pushoverで通知する

6. 最終送信だけ人間が確認する、またはエラー時のみ人が介入する
